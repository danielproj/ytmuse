# E01 direct-native connection preparation

Current service-first production-auth composition is described in [Google auth implementation](Google-Auth-Implementation.md). The earlier candidate limitations below are historical; the stage-auth report/result supersede them for Google implementation readiness only. App registration and actual Music/native-media access remain unverified.

This slice implements anonymous Music HTTPS metadata requests and the production native Google identity candidate. Its Google implementation is ready for app-owned registration and later normal consent validation; actual Music session, native source playback, advertising, offline and Cast remain unfinished. G01–G09 remain open and V01 visual acceptance remains pending.

`PublicMusicClient` uses Music's site-published WEB_REMIX configuration for `youtubei/v1/search` and selected-item `youtubei/v1/player` metadata. Public protocol configuration is distinct from an application's OAuth client ID. Requests use no account credentials, cookies, visitor token, alternate platform, browser session, extraction or challenge bypass. The current header identifies YTMuse with macOS web compatibility. No service-denial response triggers a client switch. Historical anonymous receipts record Swift-typed video-bearing Music rows and matching detail metadata; the selected item was `UNPLAYABLE` / `Video unavailable`, with no streamingData. These observations establish neither song-only search typing nor source/distribution/media rights.

The ephemeral URLSession disables cookie/credential/cache stores, denies redirects, pins HTTPS origin/method/path/query, rejects auth/cookie/Host headers and oversized input, paces one second apart, and bounds streaming response bytes (4 MB homepage, 2 MB JSON) with request/resource timeouts. Its internal I/O/clock seam retains all production constraints; tests exercise allowlist rejection, byte consumption at the cap, the actual redirect delegate and pacing without TLS infrastructure.

Configuration TTL and OAuth attempt expiry use one injected monotonic clock per owner. Wall-clock Date is used for observation timestamps and absolute signed JWT time claims; elapsed validity uses monotonic time. Configuration expires at 30 minutes, OAuth at 180 seconds. OAuth schedules reclamation even if no callback arrives and checks deadlines again at start, callback and exchange completion. Abandoned late listener binds are closed before a newer start can acquire that listener. The production one-attempt listener/browser/verifier and lifecycle composition are implemented in stage-auth.

Search and detail receipts carry separate operation UUIDs plus shared owner generation, `hl`, and optional `gl` (nil means server default). Search also carries the exact query in memory. New searches supersede older searches; they do not invalidate detail requests. A newer detail for the same item supersedes its predecessor, while separate item requests remain independent. `invalidate()` invalidates all work/configuration on ownership changes. Consumers must wire invalidation to lifecycle changes before UI integration. These anonymous receipts contain no authenticated account/channel context. Results are capped at 25 and `coverageComplete` remains false; other entity categories and pagination are unsupported.

Parsing preserves array ranking. An object may have only one branch containing supported responsive rows; multiple unordered renderer-bearing branches raise shape error. Error/unknown/empty shapes never become confident empty catalogs. Detail validates returned video ID. Metadata/status observations expose no playable URL.

`DesktopOAuthFlow` builds PKCE S256 browser authorization with independent secure state/nonce/verifier and validates exact callback origin/method/path/Host, duplicate parameters, lifetime, generation and one-use consumption. It rejects denial, replay and cancelled/stale results. `DesktopOAuthTokenExchange` constructs bounded direct HTTPS token POSTs and validates required grants before calling a mandatory injected cryptographic verifier. Only documented profile/email identity aliases are normalized; openid and YouTube readonly remain exact required grants. URL-form grant behavior is covered by synthetic tests. The review considered its live Google applicability plausible, not independently observed; no actual token exchange occurred.

There is no unsigned-JWT fallback or default accept-verifier. The production `GoogleJWTVerifier` performs signature/JWKS, issuer, audience, time, nonce and subject validation. The coordinator retains verified Google grants in an exact separate app-owned Keychain record with revocable permits, scopes refresh/replacement to the initiating lifecycle owner, and removes locally before best-effort revocation. See [Google auth implementation](Google-Auth-Implementation.md) for the complete production policy, developer configuration and ordinary test coverage. Registration/real consent acceptance remain unverified; no actual token exchange or Music session has been observed. The default source-session bridge returns no proof and cannot install Music Connected.

Run `scripts/test.sh --suite T51` for deterministic headless tests. `Tests/ConnectionProof/run-public-observation.sh` is an explicit optional anonymous network diagnostic. Each run creates a fresh UUID directory under `artifacts/harness/nodes/E01/observations/`, saves exclusive files and hashes the actual sanitized projections. It never overwrites pinned `capture-0.json`, `capture-1.json` or historical receipts. Cancellation, timeout, network, shape, HTTP and other errors have separate sanitized categories; failure is recorded before the test fails. The fixed public diagnostic query may be recorded; private search text and arbitrary exception messages are not logged.

The prior canary claims were unsupported. `historical-success-configuration-receipt.json` is the unchanged successful numeric-version receipt formerly misnamed `configuration-variant-failure.json`. Historical report/results and exact critic evidence remain under `rework-1/`. Canary strings in parser tests are synthetic resilience cases only. No retained receipt proves a canary failure or canary final run.
