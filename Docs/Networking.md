# Bounded direct adapter infrastructure — W07 rework 1

This is shared native Swift infrastructure alongside the reviewed E01 `PublicMusic.swift` transport. E01/OAuth/Domain/Queue/Persistence/UI/glass files remain unchanged. No Music operation, stream, credential bridge or new access grant is enabled. Runtime uses URLSession directly, without a browser, Firecrawl/reference-library runtime, proxy backend or downloaded code.

## Account authority and feature queries

Each `BoundedNetworkClient` is a feature owner. Its `RequestContext` includes its own query generation. Clients share a `NetworkScheduler`; the scheduler owns an injectable `NetworkAccountFence`. Binding a client publishes the **account generation** to that fence. Every network request checks it before credentials/admission, immediately before I/O, after I/O, and before publication. An owner forgotten during an account switch therefore cannot send or publish an older epoch. Equal-generation identity changes on one client are rejected. A search query advance affects only that client's tasks, never another feature's query generation.

The fence is an application/session epoch, not a global static order over all possible sessions. Concurrent explicitly bound account/background owners may share an epoch. Advancing the epoch invalidates all older owners using that fence. A background owner intentionally surviving an active-account switch must use a separate explicit fence **and separate coordinators**, with its own lifecycle/removal handling. Never obtain that behavior by omitting generation checks or sharing incompatible authority domains. The normal default clients share one scheduler/fence and transport. Application composition must publish the authoritative detached epoch on logout/removal and inject the same fence into its cache/refresh facades; the primitives cannot infer W04 lifecycle transitions by themselves.

`SourceCache` and `CredentialRefreshGate` are facades over shared coordinators. Their bindings and coalescing keys use account/channel/region plus account generation; **query generation is not a shared high-water mark**. Default facades share backing coordinators, so separate feature facades can coalesce. An isolated session/test can inject its own coordinator. Moving a facade's binding does not globally cancel another account owner. Resource invalidation removes only that resource's entry/flight; account invalidation is explicit. `invalidate()` on a facade clears its current account scope; coordinator `invalidateAll()` is the deliberate all-scope reset.

For query-specific consumers, each feature keeps a `NetworkQueryOwner` and passes its `NetworkQueryToken` on reads/refreshes. Supersession is checked only against that caller's token. Without a token the caller explicitly requests an account-scoped snapshot, not a UI query freshness guarantee. Every cache result echoes the individual initiating context; `refreshScoped`/`refreshAccount` do likewise. The legacy reference-only refresh accessor is for internal account-owned consumers that do not publish feature state.

Use `readShared`/`refreshAccount` to give the producer an account-level context with query zero. Its underlying network/credential owner must belong to that account operation, independently of every consuming feature. Do not capture a feature-owned client's query in a shared producer: rebinding that client would invalidate valid peers' underlying work. The tests exercise a real account-load client while a consuming query becomes stale, as well as the exact critic Y2/Y3/Y4 sharing scenarios. No provider-specific account-load client is composed into the app in this lane.

## Admission, retries and lifecycle

The scheduler grants at most six metadata/artwork transfers and two media transfers, reducible under contention (e.g. media one in Low Power Mode). It scans requests in arrival order **among ready requests**; paced/cooling keys are skipped without taking capacity or advancing their pacing state. A successful handoff alone commits the per-account/channel/region/host start interval (default 200 ms). Rejected and cancelled queued admissions do not burn reservations. This allows another account/host to proceed during a backlog's cooldown.

Pending admission is bounded to 256 acquisitions, with 128 tasks per feature owner and a per-request admission deadline. A continuation queue is driven by release/cancellation plus one earliest-readiness/deadline timer, rather than 10 ms polling. Cancellation racing with a successful handoff returns its permit exactly once. Production uses the injected monotonic time domain; tests include manually advanced deadlines and fair handoff without clock advancement.

Only routes explicitly classified `knownRead` can retry; GET/POST method is not permission. Mutations and unknown actions are attempted once. 401/403 are terminal and never trigger an automatic refresh loop. Transient reads have at most four attempts and a bounded retry scheduling budget (default three attempts/20 seconds), with exponential backoff and injected jitter. The budget governs further attempts/waits; admission and each actual response also have their own deadlines.

Retry-After accepts delta-seconds and IMF-fixdate, RFC 850 and asctime HTTP dates. Date conversion alone uses the injected wall clock; waiting uses monotonic time. Meaningful delays within a day are preserved in full, with remaining delay surfaced to later admissions. A bound exceeding the retry/admission budget is returned rather than retried early or slept indefinitely. Values longer than one day are treated as implausible: their original numeric value is surfaced, automatic retry stops, and the shared key is quarantined for at most one day. A later explicit request may try again after that horizon. No indefinite process-lifetime cooldown is installed, and a ten-minute bound is not shortened to a few minutes.

Default clients reuse `DirectBoundedTransport.shared`. Explicitly owned transports have a shared lifetime owner across value copies; its deinit invalidates the session, and public `shutdown()` calls `invalidateAndCancel` idempotently. Application shutdown should close the shared pool; feature teardown cancels its tasks without shutting down peers' shared session. Tests verify explicit shutdown stops an active URLProtocol transfer and rejects reuse. This lane does not edit the app lifecycle/UI composition.

## Shared waiters and refresh finalization

Each shared-flight consumer has an independently resolved continuation. Task cancellation resolves that caller immediately as `.cancelled`; it does not wait for a loader that ignores cancellation. Cancelling one waiter leaves valid peers intact. The flight alone finalizes storage and clears itself. If a public read loses its last interested waiter, it cancels its loader; late completion cannot repopulate an invalidated/replaced entry. Pending query/fence-invalid consumers cannot suppress valid peers' caching. Storage policy is intersected across the remaining valid consumers, and response headers always constrain it.

The default refresh coordinator is cancellation-safe mode: the last abandoned waiter cancels the provider. Do not use that mode blindly for a source that rotates credentials after dispatch. Such a source must explicitly inject a coordinator with `ownedFinalizationSeconds` (positive, at most 120 seconds). Caller waits are still immediately cancellable, while the already-owned operation may finish protected retention within that bound. At expiry callers receive timeout and the provider is cancelled; an uncooperative provider retains an expired tombstone until it actually exits, preventing overlapping rotations. Scope removal invalidates waiters and drops late references. No reference can become a UI result after a removed/superseded account scope or caller token.

This coordinator never installs credentials. An actual rotating provider must atomically fence protected-store installation in its credential owner, obey its bounded I/O/finalization contract and reconcile an ambiguous rotation before another attempt. A cancellation-ignoring injected closure cannot be forcibly terminated by Swift; its late result is ignored and it cannot authorize publication. No real refresh provider, non-cancellable protected-store write or atomic vault finalizer is installed or verified here. OAuth profile plumbing is not presumed to grant Music access.

## Policy, wire and resource bounds preserved

Trusted native composition supplies a fixed `Set<NetworkRoute>` established by source/access review. Each route binds exact HTTPS host, encoded path, method, query-name set, purpose, credential permission and replay classification. Request construction rejects userinfo, explicit ports, fragments, path aliases, unknown query keys and excessive URL/body sizes. Never construct policy from deep links, untrusted JSON, redirects or remote configuration; no routes are enabled by default. Local-device/update purposes belong outside this Music adapter.

Only protected `CredentialReference` values cross the model boundary. An optional resolver must validate exact account/channel/region/generation and obtain ephemeral authorization from protected storage. Requests cannot supply arbitrary headers. Ephemeral sessions disable cookies, system credential storage and URL cache. Standard TLS remains unchanged and every redirect is denied, including same-origin. Diagnostics and ordinary/debug descriptions include no URL, query, body, provider error text, header or credential value. `sendEnvelope` preserves initiating context on failures/successes, including numeric rate-limit information.

URLSession's decoded bytes are collected incrementally: advertised length is rejected early; delivered bytes stop at cap+1 reads even without a correct Content-Length. Default cap 4 MB, configurable 1 byte–16 MB. Per-attempt response deadline is positive up to 120 seconds, with native session timeouts as well. The new owned-session lifecycle leaves the reviewed byte, TLS, redirect and cancellation policies intact. Media responses here are bounded chunks, not a completed retained download/entitlement/variant integrity implementation.

`NetworkDecoder` parses off MainActor with pre-decode JSON nesting/work/byte limits. Missing/partial/type-mismatched required fields fail locally; optional unknown fields remain compatible. HTML MIME on JSON is a distinct content fault. Images are inspected for dimensions/page count before only a bounded thumbnail is decoded (default edge 2048, maximum 4096; default source pixel cap 16 million, maximum source edge 16384). These checks do not claim hard preemption inside ImageIO/JSONDecoder or source-specific media-probing acceptance.

The memory cache defaults to 16 MB/256 entries. Opaque resource IDs must denote the same source request independent of consumers. Actual source retention permission is required (zero means no storage). Freshness defaults 5 minutes dynamic, 15 minutes membership and 24 hours stable can only shorten under source policy/Cache-Control/Expires/Age; no-cache is conservatively not retained. `cached()` supports immediate display; visible stale reads refresh and hidden reads never load. No persistent cache or conditional ETag/304 implementation is claimed.

Occurrence accumulation still validates cursor account/context/collection/expiry and deduplicates by stable occurrence ID, preserving repeated media items. It caps at 100,000 rows and requires actual source cursor/identity semantics. `DurableMutationExecutor` still claims W03's outbox durably before submit, requires an explicit operation acknowledgement rather than HTTP 200, leaves ambiguous submission needing reconciliation and never replays a claimed operation. Authorization, provider conflict reconciliation and source cache invalidation after real writes remain source/command composition obligations.
