# Native glass integration recipe

The authoritative addendum is [Visual-Direction.md](Visual-Direction.md). The original specification remains unchanged. V01 styles the currently implemented welcome, local accounts and appearance Settings. W09/W21/W27 extend this foundation to their real features; they must not add decorative placeholder controls.

Use `MusicCanvas` once behind a window's content. It is a static, low-opacity red/neutral wash on the semantic window color, with no timer, blur bitmap, artwork palette dependency, or animation. Native title bars, traffic lights, sheets, alerts, dialogs, pickers, focus and menu behavior remain system-owned.

Use `MusicGlassGroup` around each control region. It wraps the real `GlassEffectContainer` with 8-point joining distance, below the normal 16-point gap, so unrelated controls do not merge at rest. Use `musicSurface()` on region panels after layout padding. Do not put a glass effect on every cell of a large scrolling collection: W09 should use one background per browser/sidebar/inspector region and native rows with semantic selection. Group related glass controls and avoid nested surfaces that do not add meaningful depth.

Use `musicButtons()` on native Buttons/SettingsLink and `musicButtons(prominent: true)` on the primary action. These apply real `.glass`/`.glassProminent` primitive styles, preserving role, disabled state, native hover/press/focus and keyboard activation. Use destructive roles plus descriptive labels; never convey state by tint alone. The red accent decorates the canvas; essential text always uses semantic primary/secondary colors over regular glass, independent of artwork.

`GlassPolicy` resolves Reduce Transparency or increased contrast to opaque semantic window surfaces with visible primary-color boundaries. Low Power Mode or inactive scenes use regular native material and bordered controls. Power notifications update this policy without polling. Reduce Motion, inactive scenes and Low Power Mode remove custom transaction animations. No V01 component starts decorative animation, even in normal mode, so hidden/occluded windows have zero ongoing decorative animation work by construction. W21 must connect any future animated content to actual per-window visibility/occlusion; scene activation alone is not an occlusion detector.

Spacing tokens are 8/16/24 points; panel corners use a continuous 24-point radius. Native fonts scale by semantic role. Account rows expand and their action layout falls back from a horizontal group to a vertical group; do not impose fixed row heights. Keep reading order and focus order aligned. Prefer native controls to custom gestures; preserve keyboard Cancel/default actions in sheets.

W09: browser/sidebar/content regions, semantic table selection and bounded view creation. W21: player/queue/lyrics/menu popover/mini-player/Now Playing and actual window occlusion gating. W27: full native Settings categories, long text/RTL layouts and per-category defaults. W28/W44: full VoiceOver, localization, contrast measurements and resource profiling. None of these future surfaces or performance acceptance is claimed by V01.

Primary references: [Apple custom Liquid Glass](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views), [Icon Composer workflow](https://developer.apple.com/documentation/xcode/creating-your-app-icon-using-icon-composer). Cached primary-source captures and installed-SDK signatures are retained with V01 evidence. No reference implementation code is copied.

V01 native validation found that system secondary text could become too pale over the light panel. Use `MusicStyle.secondaryText` for secondary copy: it resolves to an opaque adaptive gray independent of glass vibrancy. Fifteen recorded text regions (six glass, four opaque surfaces and five account headers over canvas) in the native matrix are checked against local screenshot backgrounds by `Tests/DesignSystem/MeasureGlassContrast.swift`; this is sampled contrast evidence, not complete accessibility certification.

Run `scripts/test.sh --suite T50` for provenance, all package regressions and the native visual/action suite. The separate test host ignores persisted window restoration and is launched by exact sibling product URL, avoiding stale installed app copies. The production lifecycle test still exercises actual process restart and persisted appearance.

The Latin keyboard fixtures use `scripts/test-native-latin.py` and the public Carbon input-source API. It selects only an already enabled/selectable ASCII-capable source (U.S., ABC or another available source), records the original ID, and attempts restoration/verification of that exact ID using three consecutive fresh helper reads after success, failure or catchable INT/TERM/HUP. The first signal is recorded without raising; subsequent signals cannot abort child teardown, source restore/verification or atomic receipt writing. The original exit/interruption outcome is retained after successful cleanup. Failure to verify restoration is explicit exit 70; OS refusal while the console is locked can require a verified cleanup after unlock. SIGKILL and power loss cannot be caught or guaranteed. It installs/enables no input method and changes no persistent keyboard configuration. This is a test prerequisite only; YTMuse remains layout-independent. If no eligible source exists or selection is refused, the test setup exits 75. Keep the input receipt with native results. Source text and clipboard contents are never recorded by this helper.

The Low Power/inactive `simplified` view mapping has policy-test coverage only. It has not been rendered/captured, and macOS scenePhase changes on app deactivation have not been observed. W21/W44 must verify the rendering and any visible restyle on app switching; no runtime mapping acceptance is claimed here. The original matrix Settings Tab press has no focus assertion and establishes no tab-order behavior. A supplementary source-switch-free native case asserts app-level digit input reaches the rename alert’s initial text-field focus, then Escape dismisses it; it also asserts the compact Open Settings action starts offscreen, becomes hittable after scrolling and opens the test host’s native Settings. Broader keyboard/tab-order accessibility remains with W28.

## V02 polish layer (GLASS07–GLASS11)

Feature and shell code never states a radius, material, animation curve, raw Liquid Glass call or literal spacing. `Packages/NativeMusic/Tests/GlassPolishTests/SourceGuardTests.swift` fails the build of the test suite if one appears outside `Sources/DesignSystem` (its exemption list is empty).

- **Radius scale** `MusicRadius`: 4 / 8 / 12 / 16 / 24 / 32 (xs…xxl). Feature code asks for a semantic `MusicCorner` (`.badge`, `.selection`, `.thumbnail`, `.artwork`, `.media`, `.feature`, `.panel`, `.player`) through `musicClip(_)`, `musicOutline(_)`, `musicSelectionBackground(_)` or `MusicCorner.shape`. A nested shape is concentric: `MusicRadius.inner(of: outer, inset:)` (outer − inset, never negative).
- **Spacing** `MusicSpace`: 4 / 8 / 12 / 16 / 24 / 32 on a 4 pt grid (`hairline` 2 pt only inside badges). `MusicSpace.isOnGrid` is what the audit uses.
- **Elevation** `MusicElevation` (`flat`, `raised`, `floating`, `hero`) through `musicElevation(_:tint:)`; none under Increase Contrast.
- **Motion** `MusicMotion` tokens keep the MOTION budgets and now resolve to springs and smooth curves (`hoverPress`, `selection`, `playPause` snappy; `artworkExpansion`, `miniPlayer`, `playerMorph` springy; `navigation`, `reveal`, `loading`, `artworkColor`, `lyrics` smooth). `musicAnimation(_:value:)`, `musicTransition(_:)`, `musicWithAnimation` and `MusicMotionContext.perform` resolve them against Reduce Motion (only 0.1 s crossfades remain), Low Power Mode, scene phase and `musicWindowVisible`, which the window root publishes with `musicWindowEnvironment(visible:)`. A hidden window animates nothing.
- **Glass** `musicSurface(_ corner, tint:, interactive:)` for regions; `musicGlass(_ corner)` / `musicGlassCapsule()` / `musicField(focused:)` for small elements; `musicBarBackground()` for edge-to-edge bars; `musicGlassID(_:in:)` for identity morphs; `MusicGlassGroup(spacing:)` wraps `GlassEffectContainer`. All resolve through `GlassPolicy` (opaque outlined, simplified material, native glass).
- **Tactile feedback** `ButtonStyle.musicTile(_:)` (hover lift, press settle, hairline), `musicHoverLift()` (cards), `musicHoverHighlight()` (rows).
- **Artwork light** `MusicTint` solves the opacity at which an artwork colour may wash glass so secondary text keeps ≥ 4.5:1 over the tinted backdrop in light and dark. The artwork never decides legibility.
- **Layout audit** (`LayoutAudit.swift`): `.audit(name, group:, kind:, within:, alignLeading:, onGrid:)` reports frames (identity in Release); `auditRoot` collects them; `LayoutAudit.evaluate` checks sibling overlap, containment, grid offsets, shared leading edges and equal grid-aligned outer margins. `scripts/test.sh --suite T52` runs the rule tests, the guard and the headless render audit of every primary surface at the minimum, default and a large size in light and dark.

### Rework 1 additions

- **The player is one glass shape that expands.** The bottom bar and Now Playing (the expanded player, `ExpandedPlayer`) live in one player layer inside one `MusicGlassGroup`, share the glass identity `player-surface` (`MusicMorph`, via `musicSurface(…, morph:)`) and one namespace, and only one of them exists at a time. Switching them (an animated state change, `MusicMotion.playerMorph`) morphs the glass shape; artwork (`current-artwork`), title, artist and controls carry matched identities (`playerMatched` / `musicMatched`) for owned media and YouTube Music alike. Fallback paths morph the backing shape; Reduce Motion drops every matched identity and crossfades (0.1 s); Low Power and a hidden window switch instantly. The destination `.nowPlaying` keeps its navigation entry; Now Playing grows out of the detail panel's corner and never covers the sidebar.
- **Audit**: regions (panels, the player bar, chrome bands) are mutually exclusive across groups (a floating player is an overlap); regions and bands must stay inside the window content; `alignTop` keeps every page title at one height (24 pt below the panel top, on the grid); grid offsets are live for page titles; a top-edge margin rule joins leading, trailing and bottom.
- **Tint**: `MusicTint` is a model solved at the lightest and darkest plausible glass backdrop (dark 0.03–0.10, light 0.70–0.95) with alpha blended on encoded sRGB; the test recomputes the contrast independently over the whole range. Secondary text is `MusicStyle.secondaryGray` (dark 0.86). White or yellow artwork therefore gets almost no wash by design.
- **Fields** (`musicField`) draw a hairline when glass is simplified to a material, so they have an edge in every mode.

### Rework 2 additions

- **Reduce Motion** is a 0.1 s opacity crossfade between the bar and the expanded player (`MusicTransitionKind.morphSwap`, `MusicMotion.playerMorph` keeps a 0.1 s curve under Reduce Motion); the glass morph and every matched identity stand down. Outside Reduce Motion the swap has no fade of its own (a view at opacity 0 takes no clicks, and the incoming bar must take the click that follows Back).
- **One tint across the morph**: the player's artwork light is held once at the shell (`playerAccent`: the YouTube Music cover's while it plays, the window artwork's otherwise) and handed to the bar and to the expanded player, so the glass tint does not drop out when one becomes the other. Accent results are ordered (`AccentSequencer`): only the artwork still current may publish its light.
- **Expanded transport**: the transport and its accessories never share space (`ViewThatFits`: one row while both fit, accessories under the controls otherwise); both are audited (`nowPlayingControls`, `nowPlayingAccessories`).
- **Derived corners** are capped to a quarter of the element's edge (`MusicCorner.radius(forEdge:)`, `musicClip(_:edge:)`), so the 40 pt compact thumbnail is not a circle.
- **One accent in the bar**: the prominent play/pause is tinted with `MusicStyle.accent`, like the sliders. Secondary text in dark is gray 0.82.

## Deep dark (2026-11-04)

The dark appearance no longer uses the system's window grays. `MusicPalette.darkCanvas` (white 0.010) is the window canvas and the sidebar column (`musicSidebarColumn()`), `darkPanel` (0.045) fills opaque region panels and small opaque glass fallbacks, and `darkCard` (0.085) fills `musicInsetSurface` cards so they still separate from their panel. Native glass and its simplified material carry a black scrim at `darkGlassScrim` (0.5) inside their shape, so panels stay dark over a light desktop or bright artwork; the canvas's accent glow drops to 0.06 and loses its white lift in dark. Light appearances are unchanged. Light text only gains contrast as these fall; the dark content and glass backdrop ranges now start at 0, and the contrast audit still passes.
