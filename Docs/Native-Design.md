## Rework-2 availability and current artwork

Saved window state is a secondary feature, not an account-activation gate. Its store advances account/generation authority before checking storage and reports history off on known filesystem/metadata failures; it never restores or writes unverified private records while off. Stale authority and cancellation remain distinct errors. A prior owner's pending flush is not admitted as a prerequisite for a different owner. The UI shows a localizable notice while accounts and other features remain usable.

Recovery requires the explicit native “Reset saved window state” confirmation, describing only this app's saved navigation/search/filter/selection state for all accounts; listening history, accounts, music and remote data are excluded. Reset validates the dedicated path, ownership and known entries, unlinks symlinks without following them, refuses unknown/nonempty directories and never recursively erases outside it. It drops pending snapshots, advances a persisted history epoch before purge and retains a reset-in-progress marker on partial failure. Older snapshots cannot repopulate cleared state, including after restart; known removal revocations persist and failed purges remain revoked/retryable. No automatic corruption-hiding deletion occurs.

Tint publication now includes the artwork resource/policy/request owner and originating consumer identity. A window's own current nil palette clears its accent; late old-resource/owner/renderer nil callbacks cannot clear a newer valid one. No-art requests immediately show no tint. Real offscreen hosted-consumer controls exercise these transitions. CurrentArtwork mounting controls additionally verify compact withdrawal/restoration during expansion/reversal; actual desktop observation remains W09-E1.

## Rework-3 recovery continuity

Persistence availability no longer clears live navigation. A current owner keeps every live window's destination/back-forward/query/filter/selection/scroll after a save, restore or close-save failure; persistence remains off and old stored data cannot overwrite later user edits. Registration uses account ownership independently of persistence status. Real account barriers/removal still retract immediately, and only the explicit confirmed reset clears the named state.

Foundation atomic publishes are serialized by the store actor and a cooperative nonblocking directory lock shared by publish/reset. Explicit reset recognizes only canonical metadata/record targets with the observed `.sb-<8 hex>-<6 alphanumeric>` suffix, owned regular single-link bounded files with0600/0644 modes (the actual Foundation probe observes0644 before final chmod). Staging contents are never restored or interpreted. Unknown, unsafe, symlinked or directory staging entries refuse recovery; outside targets remain untouched. A publishing lock prevents cleanup during active cooperating writes. Marker-at-start keeps normal restore/write off until explicit recovery completes. Finder `.DS_Store` remains deliberately unknown; no broad hidden-file deletion is performed. These are owned-file recovery checks, not native desktop interaction acceptance.
