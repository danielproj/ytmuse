# Home, Explore and catalog details (W11)

Design notes for the native catalog screens. The parser is built on nine REAL anonymous public captures (`Fixtures/W11-real`, labelled `real-public-anonymous-capture`) and tested against them first; `Fixtures/W11` holds only the edge cases the captures don't show, labelled `synthetic-test-only`.

## Reading the service

- `MusicBrowseParser` (YouTubeMusicAdapter) reads a `browse` response into shelves of typed entries. Kinds come from each entry's own endpoints (`pageType`, `musicVideoType`), never from a localised title: `musicTwoRowItemRenderer` cards, `musicResponsiveListItemRenderer` rows (Quick picks, tracks, ranked artists), `musicMultiRowListItemRenderer` (podcast episodes) and `musicNavigationButtonRenderer` tiles (Charts, moods, genres). Sections are shelves (carousel, list, grid, categories), header sections (an album's `musicResponsiveHeaderRenderer`, an artist's description), layout furniture (a chart's region picker) or unsupported (Home's taste-builder prompt).
- **Accounting.** Every section and entry is counted: `sections = shelves + headerSections + furniture + unsupportedSections`, `items = classified + skipped + unsupported + duplicates`. The tests compare `items` with an independent walk of the raw JSON for all nine captures, so a renderer that is silently dropped fails. A page with sections but nothing readable is `.unrecognised`, never an empty page.
- **Greyed-out rows.** A track the service greys out (`GREY_OUT` display policy, no watch endpoint) is listed as an unavailable song with the id it names; it is not dropped and not made playable.
- **Paging stops.** A continuation that returns the token it was asked with, or adds no new entry or section, ends paging for that shelf/page with the reason recorded; every continuation request waits for its account's next one-second slot (`ContinuationPacer`).
- **Staleness.** Home, Explore, charts and moods: 5 minutes; albums and artists: 24 hours; other pages 10 minutes. ⌘R refreshes whichever page is showing.
- **Pagination.** A page token lives on the section list (Home's further shelves, a playlist's further tracks) or on a shelf (a show's episodes). Both the classic `continuations` envelope and the newer `appendContinuationItemsAction` are read. A token is sent in the POST body only; the request URL stays `…/browse?prettyPrint=false` so the signed allowlist is unchanged.
- **Transport.** Signed (`SAPISIDHASH`, the account's session, rotation written back) when a connected account is active, anonymous otherwise, through `MusicSessionCoordinator.browse/continuation` with the same account-scope fence as search (a reply for another scope is dropped; an ended session expires the identity and answers anonymously, flagged). Same transport rules: exact host/path allowlist, 4 MB cap, identifiers validated before anything is sent, nothing logged. Catalog artwork comes from the exact image hosts (`yt3/lh3–6 googleusercontent`, `yt3 ggpht`, `i.ytimg.com`), 512 KB cap, `image/*` only, no credentials.

## Screens

`CatalogPageModel` is one page (Home, Explore, Charts, a mood, an album, an artist, a playlist, a show). It keeps a session-only cache per account scope (never on disk), labels data **live / saved copy / stale** (stale after 10 minutes, labelled until a refresh lands; a failed refresh keeps the older page and says so), and fences every reply by request generation and account scope.

- **Refresh keeps what is visible** (`CatalogMerge`): shelves and entries the person has keep their order; new shelves and entries are appended after them; a shelf the service dropped goes unless it is the shelf at the top of the viewport (the anchor); pages loaded by pagination survive. Shelf identity is layout + title (the service's shelf ids on Home are generated per response).
- **Lazy pagination:** reaching the end of a shelf or page loads the next one; a button does the same for keyboard and VoiceOver users; a repeated boundary entry is dropped and counted; a failed page keeps its token and the next request retries it; a second request while one is in flight does nothing.
- **Actions** go through the same performer as search: `SearchActionPerformer` → `PlaybackModel.playMusic` → the hidden player, which takes a playlist id. A song or video plays its own radio (`RDAMVM<id>`); an album, playlist or show plays the playlist the service named; a page's Shuffle is the endpoint the service published for it — the same playlist **with the parameters that make it shuffle** (album, playlist) or a distinct shuffle playlist (artist) — and those parameters travel through the hidden player (the page's router receives `watchPlaylistEndpoint {playlistId, params}`; a fresh document gets them as soon as it commits); a Shuffle that would only replay Play's playlist is never offered. Start Radio uses the published mix. A track inside an album or playlist plays that collection **from that track** (its row's own playlist + video id; a song seeded only with its own radio still plays that radio); a show's playlist is its `MPSP…` id minus the prefix. Anything the service did not publish is not offered. Every offer either runs or states why not (sign in, session ended, track unavailable, single episodes can't be played from here yet).
- **Follow and Save** are the library controls of W12 ([`Docs/Library.md`](Library.md)): drawn on a page only for a signed-in account whose page published what they act on, and sent only from an explicit press through the shared ledger. Before sign-in, or when the page published nothing to act on, a page that offers them shows one sentence saying why instead.
- **Detail pages:** album (credited artists as links, tracks with position/duration/explicit/unavailable, other editions found by title, related releases), artist (top songs, albums, singles and EPs, videos, playlists, related artists, audience, description), playlist and show (header, tracks or episodes, pagination), song (credits and album as links, availability, an honest quality line, actions). Roles come from the entries, not from titles. Writer/performer credits are not part of these responses; the credited artists are.
- **Native rich text** (`CatalogRichText`): the service's description runs become a plain `AttributedString` built from literal text (nothing is parsed as HTML or Markdown), control and bidirectional-override characters removed, body bounded (480 characters collapsed, 6,000 expanded, cut at a word), the attribution paragraph ("From Wikipedia … Creative Commons …") kept whole, and only `https` links to a short host allowlist survive (an `http` link to an allowed host is upgraded; a link whose visible text names another host is plain text).
