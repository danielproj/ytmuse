# MF-RECAP fixtures

Evidence for the signed Recap **service-message** reader (`MusicRecapParser`). See `manifest.json` for the provenance and limits of each file.

* The anonymous files are real, unsanitized public responses (no account).
* `signed-known-handler-sanitized-export.json` is a real signed-session response whose every string was replaced by a placeholder before export. It proves the response **structure**; the placeholders are not the service's words and the message's meaning is unknown.
* The redacted secondary-text keys in the signed export are not interpreted; the secondary line is withheld until a capture names them.
* There is **no** successful Recap payload here, and none has been captured. No parser for one exists.
